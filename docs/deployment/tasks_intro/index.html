Deployment Tasks

Once a certificate is issued, you need to put it to use: on a web server, mail server, firewall, load balancer, secrets vault or anywhere else that needs a trusted certificate for your domain. Deployment Tasks do this for you each time the certificate is renewed.

By default, Certify stores each certificate in the local machine certificate store and updates matching IIS https bindings on the local server. This automatic IIS deployment needs no task, and is controlled by the certificate's Deployment Mode.

Add Deployment Tasks when the certificate is needed elsewhere, or when you need extra steps, such as restarting a service after renewal.

Task directory​

The built-in tasks, grouped by what they deploy to. Each links to its setup guide. Tasks marked Management Hub need Certify Management Hub.

Web and application servers​

IIS is updated automatically, without a task. For other servers, export the certificate in the format they need, on the local machine, a network share or over SSH. See also Apache, nginx, and other web servers.

Scripts, webhooks and services​

Run your own steps, call other systems, or control services. For more on scripting see Scripting.

PowerShell ScriptRun your own PowerShell script before or after the certificate request.Run a Program or ScriptRun a program, batch file or shell script, locally or over SSH.WebhookCall a URL with the request result, using a template body.Restart a ServiceStop, start or restart a Windows service so it loads the new certificate.WaitPause for a number of seconds between other tasks.

How tasks run​

  • Deployment Tasks (post-request tasks) run after the certificate has been issued and, if enabled, automatically deployed. A certificate can have any number of them, and they run in the order listed. Typical uses are exporting files for other servers (Apache, nginx), copying to remote servers, updating a vault or appliance, and running scripts.
  • Pre-Request Tasks run before the certificate is requested, for example to open a firewall port for HTTP validation or to call your own webhook. Only some tasks can be used here, such as the PowerShell, Webhook, Restart a Service and Wait tasks.

Task triggers​

Each task has a trigger. It can run:

  • when the certificate request succeeds,
  • when the request fails (useful for notifications), or
  • only when you run it manually.

Manual tasks are useful for steps you only want to run at a chosen time, for example restarting a service during a maintenance window. You can run them from the app, or from the command line, a script or a scheduled task. The task editor shows the command line arguments to use.

Previewing and testing​

Run a single task with the ▶️ play button in the task list to test it with the current certificate. Many tasks also check their settings and connection when you preview the certificate request, without changing anything, so problems show up before a renewal depends on them.

Tasks that need Management Hub​

Tasks for network appliances, AWS, Google Cloud, Kubernetes and CyberArk Conjur run only on Certify Management Hub, or on an instance joined to the Hub. They are marked Management Hub in the task directory. Tasks marked Preview are not in a released version yet.

Deploying to other servers​
